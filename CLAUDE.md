# CLAUDE.md

## Translations

Any text the plugin outputs on the front end (e.g. via Twig filters or helpers like `EventDateHelper`) must be translated.

- Use the `eventful` category: `Craft::t('eventful', 'All day')` in PHP, or `'All day'|t('eventful')` in Twig. Use `{param}` placeholders, not string concatenation.
- Add every new message to all the files in `src/translations/<language>/eventful.php`, not just `en`.
- Recurr's repeat descriptions go through `translators/Translator.php`, which maps Recurr's message keys onto the same files.
- Don't unit test plain `Craft::t()` calls (that's just testing Craft, and breaks whenever a translation is improved). Only test our own translation logic, like `Translator`.
- Control panel strings aren't translated for now, so don't add them to the translation files. Existing `|t('app')` calls only reuse Craft's own translations.

## Docs

- Admonitions need a blank line between the `!!! type` line and the indented body. Otherwise Prettier (run by lint-staged) treats the body as a paragraph continuation, strips its indentation, and the box renders empty.

## Releases

Releases are automated with semantic-release on every push to `main`.

- Commit messages must follow Conventional Commits; they decide the next version (`fix:` → patch, `feat:` → minor, `!`/`BREAKING CHANGE` → major). `chore:`, `docs:` etc. don't release.
- The `release` job lives in `.github/workflows/ci.yml` and `needs: check`, so nothing is released unless lint and tests pass. There is no separate release workflow.
- Pushes to `main` that only touch files that can't affect lint, tests or the released package (docs site, IDE and dev tooling config; see `paths-ignore` in `ci.yml`) skip CI entirely, so only the docs site is rebuilt. Add new files of that kind there, but never anything CI reads (`src/`, `tests/`, `stubs/`, `demo/config/`, `composer.*`, `phpstan.neon`, `rector.php`, `phpunit.xml.dist`, `release.config.js`) or that ships in the package (`LICENSE.md`, `.gitattributes`). `CHANGELOG.md` stays out too, so release commits get a CI status.
- CI concurrency only cancels in-progress runs on pull requests, so a release on `main` is never cancelled halfway.
- The version comes from the git tag only. Don't add `"version"` to `composer.json`.
- `CHANGELOG.md` is generated by semantic-release; don't edit it by hand. It must stay committed in the repo because the Craft Plugin Store scrapes it, and its headings must stay in the `## X.Y.Z - YYYY-MM-DD` format (set by `headerPartial` in `release.config.js`). Breaking changes are rendered as a `> [!IMPORTANT]` alert (set by `mainTemplate`, a copy of the `conventional-changelog-conventionalcommits@9` template), so Craft highlights them and expands the update in the Updates utility. See https://craftcms.com/docs/5.x/extend/changelogs-and-updates.html
- semantic-release pushes a `chore(release): X.Y.Z` commit back to `main` containing only `CHANGELOG.md`. It deliberately has no `[skip ci]`, so `main` always shows a CI status. On that commit the release job runs and finds nothing to release, and the docs are rebuilt so the site picks up the new changelog.
- The docs site shows the changelog through `docs/changelog.md`, which includes the root `CHANGELOG.md` with a `pymdownx.snippets` include (`--8<--`), and is placed last in the sidebar by `docs/.nav.yml`. Edit neither by hand.
